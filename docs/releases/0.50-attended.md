# Signed 0.50 acceptance on Windows

Use the owner's signed 0.50 release copy after the gate has passed on that exact file. Keep a receipt for each tested configuration on x64 Windows 11 25H2 (build 26200) or newer and Windows Server 2025 (build 26100) or newer. For a shortcut launch, record the default terminal and what the person watching actually sees on the build PC and on the second, managed PC. [Build and signing instructions](../../BUILDING.md)

## Build and move a mixed application

Start on a clean target with a fresh local folder containing `machteld.exe` and a copy of the release checkout’s `examples/mixed-migration` directory. Run these PowerShell commands from that folder. Record the OS build. Expect a `Valid` signature and match the executable hash and signer thumbprint to the approved release receipt. The expected product version is `0.50` and the Tcl package API is `30`.

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, BuildNumber, OSArchitecture
Get-FileHash .\machteld.exe -Algorithm SHA256 | Format-List Path, Hash
Get-AuthenticodeSignature .\machteld.exe | Select-Object Status, @{n='Thumbprint';e={$_.SignerCertificate.Thumbprint}}
.\machteld.exe --version
.\machteld.exe --version --api
.\machteld.exe project check --json mixed-migration/project.dict
.\machteld.exe project test mixed-migration/project.dict
.\machteld.exe project run mixed-migration/project.dict id 007
.\machteld.exe project pack mixed-migration/project.dict cards.machteld
Get-FileHash .\cards.machteld -Algorithm SHA256 | Format-List Path, Hash
```

The project declares language edition `1` and minimum API `30`. Record the signed executable’s hash as the host containing the compiler used by `project pack`, and the archive hash as the identity of the delivered copy. Expect an empty diagnostics array, two passing examples and `Inventory ID: 007`. Copy just the executable and archive into a fresh recipient directory. From an unrelated working directory, invoke both by full path and pass `id 007` to the archive. Expect the same caption. [Mixed Tcl/X sample](../../examples/mixed-migration/README.md)

For the editable-source check, run the recipient’s `machteld.exe --docs get "machteld/guide/application-compiler#editing-a-delivered-application"`. Follow the recipe to extract `working-source` and `local-compiler` from the verified archive. In `working-source/captions.src`, change the caption separator from `: ` to ` / ` and update both examples. Use the extracted `local-compiler/driver.tcl` to check, test and pack into `revised.machteld`. Record both archive hashes and run each with `id 007`. Expect `Inventory ID: 007` from the delivered copy and `Inventory ID / 007` from the revision.

## Observe the shortcut and terminal

Create an Explorer shortcut whose **Target** contains the fully quoted executable path, the fully quoted path to the original `cards.machteld`, and `--gui shelf A-17`. Set **Start in** to an unrelated local folder. Double-click the shortcut, observe startup, click **Refresh**, then close the window. Record whether a console flashed, whether the Tk window received focus, and whether its label showed `Shelf: A-17`. Run the same command from an existing terminal and verify that the shell waits until the window closes. [Shortcut format](../packaging.md)

For standard streams, save this fixture as UTF-8 `stdio.tcl` beside a copy of the same signed executable in a separate test folder.

```tcl
package require machteld 30-
puts [gets stdin]
puts stderr STDERR
exit 37
```

In PowerShell in that folder, run `.\machteld.exe stdio.tcl`, enter `007`, and record stdout, stderr and `$LASTEXITCODE`. Expect `007`, `STDERR` and `37`. Start it again and press Ctrl+C while it waits for input. Record how the shell regains control. Exercise a pipe and file redirection with the following commands.

```powershell
cmd /d /c "echo 007|machteld.exe stdio.tcl >stdout.txt 2>stderr.txt"
$LASTEXITCODE
Get-Content stdout.txt, stderr.txt
```

Expect exit `37`, `007` in `stdout.txt` and `STDERR` in `stderr.txt`.

## Exercise an update on the managed share

Use an owner-designated writable test directory on the actual share. Supply its path as `$share`. Copy the signed executable and original archive there and compare their hashes with the local receipt. From the managed desktop, run the shared copy and use its path in the shortcut test. Set `$launchTest` to the absolute path of the matching checkout’s `test/app_launch_test.tcl`.

```powershell
$sharedExe = Join-Path $share 'machteld.exe'
$sharedApp = Join-Path $share 'cards.machteld'
Get-FileHash -Algorithm SHA256 -LiteralPath $sharedExe, $sharedApp, $launchTest | Format-List Path, Hash
& $sharedExe $sharedApp id 007
& $sharedExe $launchTest $share
$LASTEXITCODE
```

Expect `Inventory ID: 007`, then `ALL APP LAUNCH CHECKS PASSED` and exit zero. The fixture creates a temporary directory on the share. While an A session and its worker are active, the fixture publishes B to the same archive path. It checks that a fresh launch sees B, the original session and its new worker still see A, and a mismatched digest is rejected. [Share test source](../../test/app_launch_test.tcl)

For the porting application, repeat its managed update and restore procedure with a copy of its external data. Record the hashes of the prior working delivery and the proposed delivery, the outcome in the open session and in a new session, and the restored behavior. Retain the expected result, observed result and pass, fail or unavailable status with each receipt.
