# Qualification for the 0.30 release

The release target is Windows x64. The owner signs a copy after the complete
unsigned executable matches across two clean build environments. The next
published release after signed 0.21 is 0.30.

## Build and reference measurements

The build PC used signed 0.21, SHA-256
`1027eef12fdb5512fb28cebb539abfac798fa32f055ec62c82e48a56ca51f3f7`.
The bootstrap now checks the implicit GCC default-manifest object used by the
linker. Its expected SHA-256 is
`d2a37dc06a868339fb0e6dcddebfae1656bd7e9e62ea1c70df4458e195ef7783`.
The release comparison uses the same source commit and commit timestamp on
the PC and the hosted Windows runner.

The reconciled pre-0.30 baseline at `a5bc5a2` passed all 67 unattended
gate steps on the build PC in 3,181 seconds, including native analysis and
two fresh reference generations. Its complete unsigned SHA-256 was
`20e9925f00ddb738e07a91fac9267bd2ad61c8b33651dfa35d060de6a4ef4c18`.
The corresponding [hosted Windows build](https://github.com/anafalanx/machteld/actions/runs/45721608153)
uses the same commit and epoch. This baseline is separate from the 0.30 candidate.

The Graphviz comparison used independently generated references, cold
dependencies, the production packager and a shared epoch of 1795643861.
The full-SQL baseline at `c8e6d9e` measured 13,731,656 bytes. With static
Graphviz and Expat at `5f44663`, the executable measured 14,566,440 bytes,
an increase of 834,784 bytes. Private desktop tests drew an HTML table with
named ports, selected a cell by clicking it, and checked its geometry.

A second comparison kept the native host fixed and changed the embedded
reference. Each timing below is the median of seven fresh processes on the
build PC, alternating the order of the two executables. Peak memory is the
median observed peak process working set. These are development measurements
on a shared machine.

| Measurement | Previous full reference | SQLite FTS5 reference |
| --- | ---: | ---: |
| Complete executable | 14,596,194 bytes | 11,644,334 bytes |
| First bounded section query | 1,175 ms | 528 ms |

Both reference builds include 249 upstream Tcl manuals, 177 Tk manuals, and
four cffi manuals. Two fresh offline generations of the same 481-page corpus
matched byte-for-byte across all ten pack files. Public retrieval reproduced
all 481 page digests and the bounded text for all 3,750 sections. The
generator independently checked the source-specific attribution and foreign
keys. After adding browser and audio documentation, the packaged runtime
at `b43da1d` reproduced all 484 page digests and all 3,795 sections. Its
complete executable measured 11,799,124 bytes with SHA-256
`521122edadaac30e977f5e7ce2583e1a20e75d16bedd2333f760969879c26da6`.

## Windows integration evidence

| Capability | Build-PC check |
| --- | --- |
| SQLite | Typed and numbered bindings, FTS5 queries, contended backups, corruption rejection and restore were exercised through a packaged Tcl host. |
| File catalog compatibility | Seed-zero XXH3 matched 18 previously recorded catalog values, including incremental and whole-file input. |
| Cloud files | A registered temporary cloud provider counted zero fetches during local-only reads. Resident and online-only files, changes in residency, and open-handle lifetime were exercised. |
| Desktop catalog | An isolated desktop exercised application discovery, lazy Tk icons, stale window identifiers, associations, and teardown. |
| Browser | Installed Edge and Chrome exercised app-owned profiles, selected tabs, cancellation, ready events, exclusive ownership, stale receipts, reattachment after the controller exited, and orderly close. |
| HTTP and UDP | An open HTTP response delivered binary data before EOF. Tests covered cancellation and slow readers. Datagram tests covered IPv4 and IPv6 loopback, message boundaries, notification cancellation, Tk delivery, and interpreter teardown. |
| Audio | Original MP3, AAC-LC and HE-AAC fixtures decoded under uneven chunking. A local HLS stream delivered 26,624 silent frames through the Windows audio endpoint. Audible playback requires a listener. |
| Authenticated network time | The Windows client exchanged TLS 1.3 keys with an independent OpenSSL peer and verified authenticated UDP replies on loopback. The packaged client passed 50 protocol checks. A previously intermittent 550 ms timeout passed 64 consecutive runs after the deadline fix. The 96 native lifetime cases ended with 127 handles, matching the starting count. |
| Direct2D and Direct3D 11 | An archived Tcl app passed 73 rendering and lifecycle checks on an isolated desktop. Pixel readback verified Intel Iris Xe and Microsoft WARP. | App migration and recovery | All 13 synthetic scenarios passed. Two versions of a Tcl-only archive shared a relocated installation. They preserved Unicode and binary data, rolled back a failed migration, left an existing backup intact and restored the previous profile. |

## Application compatibility

The porting application's five schema migrations and 29 prepared statements
ran against the packaged SQLite engine. Its unmodified startup still
requires its own native extension and checks five SQLite compile options
that differ from the runtime. An application-owned connection enabled
foreign keys, memory-backed temporary storage and defensive mode. One
observed behavior needs explicit handling in the port. The expression
`SELECT x'41' LIKE 'A'` returns 0 with the application's original SQLite
and 1 with the 0.30 candidate. The full application suite and its managed
desktop acceptance have their own qualification record.
