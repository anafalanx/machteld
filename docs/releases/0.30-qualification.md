# Qualification evidence for the unsigned 0.30 development baseline

These measurements identify specific Windows x64 development artifacts.
On 2026-11-27 the owner closed 0.30 as an unsigned milestone. The next
public release is 0.50, integrating the compiler and runtime. Its clean
build, signed-file and attended acceptance receipts belong to the integrated
candidate. [Release sequence and acceptance](../roadmap.md)

## Windows integration evidence

| Capability | Build-PC check |
| --- | --- |
| SQLite | Typed and numbered bindings, FTS5 queries, contended backups, corruption rejection and restore were exercised through a packaged Tcl host. |
| File catalog compatibility | Seed-zero XXH3 matched 18 previously recorded catalog values, including incremental and whole-file input. |
| Cloud files | A registered temporary cloud provider counted zero fetches during local-only reads. Resident and online-only files, changes in residency, and open-handle lifetime were exercised. |
| Desktop catalog | An isolated desktop exercised application discovery, lazy Tk icons, stale window identifiers, associations, and teardown. |
| Browser | Installed Edge and Chrome exercised app-owned profiles, selected tabs, cancellation, ready events, exclusive ownership, stale receipts, reattachment after the controller exited, and orderly close. |
| HTTP and UDP | An open HTTP response delivered binary data before EOF. Tests covered cancellation and slow readers. Datagram tests covered IPv4 and IPv6 loopback, message boundaries, notification cancellation, Tk delivery, and interpreter teardown. |
| Audio | Original MP3, AAC-LC and HE-AAC fixtures decoded under uneven chunking. A local HLS stream delivered 26,624 silent frames through the Windows audio endpoint. Audible playback requires a listener. |
| Authenticated network time | The Windows client exchanged TLS 1.3 keys with an independent OpenSSL peer and verified authenticated UDP replies on loopback. The packaged client passed 50 protocol checks. A previously intermittent 550 ms timeout passed 64 consecutive runs after the deadline fix. The 96 native lifetime cases ended with 127 handles, matching the starting count. |
| Direct2D and Direct3D 11 | An archived Tcl app passed 73 rendering and lifecycle checks on an isolated desktop. Pixel readback verified Intel Iris Xe and Microsoft WARP. A per-monitor-aware fixture crossed 96- and 168-DPI monitors and produced the expected pixels on both. Three runs under build load averaged 51.8 to 57.5 frames per second against the 60 Hz target. |
| App migration and recovery | All 13 synthetic scenarios passed. Two versions of a Tcl-only archive shared a relocated installation. They preserved Unicode and binary data, rolled back a failed migration, left an existing backup intact and restored the previous profile. |

Native validation caught an alignment defect in the audio output's PCM
queue. The corrected allocator guarantees the queue's required 64-byte
alignment. An instrumented fixture exercised 896 startup-failure and
teardown iterations without an undefined-behavior trap or a retained live
resource. The NTS transport now transfers its socket and event to the
caller after connection. A loopback lifetime fixture exercised 96 TLS
connections, including 24 deadlines, and returned to its starting handle
count of 135.

The process supervisor retains its 5 ms polling loop. With a single
sleeping child, capture and channel supervision both registered zero host
CPU at the platform counter's resolution. With 32 children the respective
samples used 1.56% and 1.53% of one logical core. The regression check
repeats a high single-child reading and fails for sustained use of half a
core. A deliberately busy control triggered it twice. The release retains
the current monitor while tracking an event-driven replacement under R9.

Two October enhancements remain deferred. S6 would add a separate deadline
for draining captured pipes whose writers outlive the supervised job. In 0.30,
the job deadline kills the tree and capture waits for end-of-stream. R21 would
pair rename notifications across separate `watch read` calls. In 0.30,
pairing applies within a single read. An application that needs an exact
directory catalog can rescan after an unpaired event. These limits are
documented in the embedded process and directory-watch manuals.

## Application compatibility

The porting application's five schema migrations and 29 prepared statements
ran against the packaged SQLite engine. Its unmodified startup still
requires its own native extension and checks five SQLite compile options
that differ from the runtime. An application-owned connection enabled
foreign keys, memory-backed temporary storage and defensive mode. One
observed behavior needs explicit handling in the port. The expression
`SELECT x'41' LIKE 'A'` returns 0 with the application's original SQLite
and 1 with the 0.30 candidate. None of the 29 statements uses LIKE. The one
GLOB expression reads a STRICT TEXT column that rejects BLOBs, and both
engines matched its text patterns identically. The full application suite
and its managed desktop acceptance have their own qualification record.

With the original application extension, the `88c8308` and `891b9d2` runtimes each passed
1,337 of 1,341 unchanged application tests. Signed 0.21 passed 1,335.
The four failures seen on the candidate also occurred on 0.21. Three
launch child scripts that lack the required `package require machteld`
entry. Adding the declaration in a separate test copy made all three pass
on both runtimes. The fourth explicitly expects Machteld to be absent.

The Tcl-only migration passed all 85 selected model and database checks.
It passed 284 of 355 tests in the wider selection. Unmodified application
startup still requires its application-owned provider. These figures
describe separate application configurations.

## Audio endpoint acceptance

Hosted Windows runs exercise MP3, AAC-LC and HE-AAC decoding, MPEG-TS
extraction, HTTP playlist updates, segment order and cancellation in the
integration group. Run the physical playback group on a Windows PC with a
working default audio output and an available Tk desktop. The same command
can run on a private Windows desktop during development.

```powershell
.\dist\0.21\machteld.exe tools/gate.tcl --group audio-device --runtime .\out\machteld.exe
```

Both hardware lanes play silence. The HLS lane checks that the endpoint
accepted every decoded frame and drained its queue. A missing endpoint, playback error
or timeout fails the group. Record the candidate hash from the gate output.
For the separate attended listening check, run
`.\out\machteld.exe test/audio_test.tcl --audible` and record what the listener hears.

### Attended Windows checks carried forward

Record the executable SHA-256 and Windows build before starting. On the build
PC, use the verified candidate. Use its signed copy on a separate managed PC.

| Check | What to observe |
| --- | --- |
| Standalone app | Open the wrapped GUI application from Explorer. Check its icon and the Details tab's application name, version and publisher. Confirm its window opens without a console flash. |
| Shortcut and terminal | Double-click a shortcut to a relocated Tcl/Tk archive. Watch for a console flash. From an existing terminal, check interactive input, Ctrl+C, shell waiting and the reported exit status. |
| Foreground and drop | Choose between two windows with the same title and record which one actually receives focus. Drag several files from Explorer, including a name with spaces and a non-ASCII name, and verify their order in the app. |
| Associated viewer | Open a local document with a space in its path and identify the application and document that appeared. |
| Graphics and input | Run the windowed application on a real display. Check resizing, display scaling and keyboard response. Record the display refresh rate and observed frame rate against the game's 60 Hz target. |
| Browser | Complete the app's sign-in in its own browser profile, then resume the same session. Record the outcome without including credentials or profile contents. |
| Audio | Run `machteld.exe test/audio_test.tcl --audible` from the matching checkout and confirm the short tone on the selected output. The silent endpoint and decoder tests have separate results. |
| Managed network and recovery | Check the application through the real proxy and managed share. Verify that an open session finishes with its old archive and a fresh session loads the update. Exercise rollback with the previous runtime/archive pair. |

Record the actual display, audio device and active adapters used. Qualifying
source-selected ping on two physical adapters requires both to be connected.
