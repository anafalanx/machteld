# Machteld 22 Beta 1

This document records the unsigned Windows x64 Beta 1 build for the 0.22 milestone.
The Tcl package name and version are `machteld 22`. Both `--version` and
`version` return `22`. The executable's Windows version information marks
it as a prerelease and identifies Beta 1 in its Comments field. The owner
selected the full Beta 1 feature set for 0.22. Its successor is 0.30, with
runtime and Tcl package version `30`.

## Beta 1 scope

| Area | Included behavior |
| --- | --- |
| Run and distribute Tcl | Run a UTF-8 entry starting with `package require machteld`. Pack a directory containing a root `main.tcl` with `machteld.exe pack appdir -o app.machteld`; start it with `machteld.exe app.machteld`. Console and GUI wrappers remain available. |
| Responsive Tk applications | The `machteld::job` package runs supervised workers with cancellation and bounded callbacks. Project Inspector and SQLite Lookup exercise that path. |
| Database access | The upstream Tcl `sqlite3` package and the key/value `store` use the same pinned SQLite 3.53.4 engine. Applications own their schema, migrations, query policies and backup guarantees. |
| Worker identity and publication | `app launch` supplies the command prefix for a worker from a script, wrapper or archive. On live archive replacement, running workers retain their version and a fresh launch sees the update. An archive prefix expires when its last process exits. |
| Shared files | `publish bytes` and `publish file` switch a completed file into place. `lock try` and `lock release` provide process-owned coordination. Terminating the owner releases its lock. |
| Tcl control flow | `scope` cleans up its supervised children and preserves the enclosing Tcl procedure's `return` and loop's `break` or `continue`. |
| Protected Windows paths | `canon`, `dirs -depth 0` and `links -depth 0` inspect metadata without requiring directory-list or file-data access. Use the `links` rows of `dirs -depth 0` to check every observed root reparse tag. Traversing directory contents still requires the appropriate permissions. |
| Desktop integration | `child start -console none` runs supervised console workers quietly. `child start -window normal` opts a child into attended presentation. `child present` can find its window after a process handoff. `::machteld::clipboard owned` checks whether this process acquired the Windows clipboard. Tk retains its usual `clipboard` command. |
| Wrapped app identity | Apps may supply their own Windows name, version and icon through the wrap manifest. Omitting the metadata retains the host identity. File inventories and packaging previews remain available. |
| Build and packaging | The Tcl build carries the established worker and transport limits, packaging inventory and application identity checks, opt-in reference for wrapped apps, and native validation. The Windows ACL regression fixture uses the OS copies of its utilities even when build tools change PATH. |

## Beta 1 verification

The Windows Server 2025 run built commit `e0db215` and passed 72 release and
desktop steps. The candidate's executable SHA-256 was
`984baeae52122f031c5fc5de6ecafb4a699ce0ada363e1a09899c4b9f11e8c94`.
A second build reused the same pinned dependency cache. It reproduced the
Windows PE prefix and the names and contents of all 2,306 embedded files.
The ZIP container differed, giving the executables different hashes. The final 0.22
candidate must still demonstrate identical unsigned executables from two
independent clean builds. [Windows acceptance run](https://github.com/anafalanx/machteld/actions/runs/45597853161) · [Candidate and build comparison](https://github.com/anafalanx/machteld/pull/5)

The run archived the tested executable, notes, source receipt and checksum
in an unsigned ZIP. Subsequent hosted CI jobs keep unsigned executables and
wrappers inside the job. The owner signs release binaries on the build PC.

## Repeating the Beta 1 smoke test

Extract the ZIP to a directory. Check `machteld.exe` against the included
SHA-256 and use the source commit recorded in the build receipt when reporting
a result. A smoke test requires only this file as `hello.tcl`:

```tcl
package require machteld 22-
puts "Machteld [version], Tcl [info patchlevel], SQLite [package require sqlite3]"
```

Run `.\machteld.exe hello.tcl`. To exercise both distribution paths, run
`.\machteld.exe pack hello.tcl -o hello.machteld` followed by
`.\machteld.exe hello.machteld`.

## Release checklist

- **Beta acceptance.** The clean Windows build was tested across the fast,
  integration, packaging, native-validation, reference-generator and desktop
  checks. It exercised live archive replacement on a loopback SMB share,
  process handoff, clipboard ownership across processes, and metadata-only
  access. These results belong to the Beta 1 commit above.
- **Dependency decision for this beta.** Use Tcl/Tk 9.0.4 with Tcl upstream
  fix `0ac314cb96` for ticket `d40d8db3fb`. Tcl 9.1.0 includes that fix.
  An upgrade is a separate compatibility change covering bootstrap, both
  hosts, packages and reference generation. A new Tcl version alone does
  not change the access rights requested by Machteld's native filesystem code.
- **Before the final release.** Triage beta regressions and close or explicitly
  disposition the runtime and build findings in section 4.2 of
  `plan-machteld22.md`. In particular, test a child closing its standard input
  early (R5), killing a completed child (R6), an exclusively held file
  (R7), large environment blocks (R13), executable lookup with an overridden
  PATH and long paths (R22), and worker handlers that complete with a custom
  Tcl return code (S4). Exercise successful detached execution from a
  compatible enclosing job (R8, R16, B1). Verify publication and cleanup
  on failed builds (B2, B3, B7, B10, B11). Record matching whole-file SHA-256
  hashes for two independent unsigned clean builds of the same revision.
  Compare the incremental build separately, accounting for its development
  provenance. Run the runtime checks and the packaged examples. Automate
  repeatable GUI tests on an isolated desktop and verify user-visible behavior
  in an attended session. Record the Windows target, interactive terminal,
  network and detach acceptance results. Run
  the gate again on the owner-signed release bytes and record their SHA-256.
  The signed distribution is a separate release decision.
- **Application adoption.** Exercise the porting application's own archive
  and migration tests, profile directory checks, worker lifecycle and
  attended sign-in on a managed desktop. The runtime tests use synthetic
  data. The application remains responsible for its policy and acceptance.

Beta 1 keeps the existing package set plus the documented job and SQLite
interfaces. A complete Tcllib bundle and a general-purpose FFI are outside
this milestone.
