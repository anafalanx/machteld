# Machteld 0.50-dev measurements
<!-- machteld-version-history: end -->

These measurements use unsigned Windows x64 builds on an Intel Core i7-1255U.
The language edition is 1 and the host package API is 30. The timings are
medians on the development machine with a warm filesystem. The most recent
run began after all project builds and qualification suites had finished.

## Compiling X source

The frozen `f6b1511` executable took **99 ms** to check the two-module
pages example from a fresh process and **118 ms** for the import example.
Packing the two took **1.17 s** and **1.18 s**. A packaged application
executes the generated Tcl directly.

The large full compile took 1.64–1.94 s across five timed runs. The two
large inputs repeat the same real module under different names. The rows
include comments and blank lines. Check-only and full compile used separate
timing batches, following a warm-up. The CLI medians cover nine launches
each. Project builds and tests were idle throughout.

## Reproducing and moving the combined runtime

Two fresh checkouts of `6942ee2` built the same 15,264,910-byte Windows x64
executable. Each build used its own freshly bootstrapped dependency cache,
the eleven pinned local inputs and `SOURCE_DATE_EPOCH=1795698771`. The
executable's SHA-256 was
`1c3ae388aea815e925c8f254abdf681fec3a2f95b0a4bdd289ab79b99ea8fa98`.
All twenty compiler files matched their source bytes. The embedded manual
held 499 documents and had SHA-256
`607459e1163bff9ccc522cb2acf0792ea1b90ff605ca432a32077cd8698df446`.

All 38 packaging steps passed on the resulting runtime. Between the
packaging gate and the separate direct runs, all 39 compiler test suites
ran on these bytes. Two further generations of the reference reproduced
the embedded database byte for byte.

Of 991 files in the two dependency manifests, 988 matched. Three build tools
differed. The static Tcl and Tk launchers contained different ZIP timestamps,
while every embedded library file matched. The SQLite DLL used to generate
the manual had a different preferred image base in each cache.

A mixed Tcl/X project passed its examples, ran from source and packed with
only the Windows system directory on the command path. After moving the
sources aside, the recipient directory contained just `machteld.exe` and
the archive. The copied application returned the expected Unicode caption.
Its recipient recovered the original files and bundled compiler, changed
the formatter, reran the examples and packed a second archive. Both archives
then produced their own expected captions from an unrelated directory.

## Moving data from signed 0.21

Both runtimes ran the original 0.21 console fixture with three arguments,
including a leading-zero identifier and Unicode. The development runtime
read the original binary store value from a copied 0.21 database. The
signed runtime then reopened that copy and recovered the new UTF-8 value
written by the development runtime.

Both versions accepted all 95 required valid JSON inputs and rejected all
188 required invalid inputs in the 0.21 corpus. Of the 35 inputs for which
the JSON suite allows an implementation choice, ten malformed UTF-8 byte
strings changed from acceptance in 0.21 to rejection in 0.50-dev. Pass
valid UTF-8 bytes to the JSON reader, or explicitly decode text in its
source encoding before passing it to the reader.
