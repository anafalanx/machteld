# Machteld 0.50-dev measurements

These measurements use unsigned Windows x64 builds on an Intel Core i7-1255U.
The language edition is 1 and the host package API is 30. The timings are
medians on a shared development machine with a warm filesystem. Repeat the
comparison on the final candidate during an idle-machine qualification run.

## Compiling X source

At `741f01d`, the loaded compiler parsed, type-checked and emitted Tcl for
the following projects. The measurements exclude reading source files,
starting the executable, running the program and writing an archive. Each
row uses a discarded warm-up followed by five or seven timed batches.
Physical source lines include comments and blank lines.

| Input | Modules | Lines | Check only | Check and emit |
| --- | ---: | ---: | ---: | ---: |
| Typed pages | 2 | 58 | 10.3 ms | 10.3 ms |
| Typed timeline | 1 | 97 | 22.0 ms | 22.4 ms |
| Typed colleague import | 1 | 106 | 14.3 ms | 15.7 ms |
| 10 copies of the import module | 10 | 1,060 | 141 ms | 154 ms |
| 100 copies of the import module | 100 | 10,600 | 1.55 s | 1.70 s |

Each synthetic copy has its own module name. The 10,600-line full compile
ranged from 1.56 to 1.90 seconds. Applications with different import graphs,
generic types and declaration sizes can have different costs.

In nine fresh processes per command, `project check` took 83 ms for pages and
84 ms for import. `project pack` took 1.12 s and 1.20 s respectively, including
writing the checked code, rebuild inputs and searchable project reference.
A packed application runs its generated Tcl directly. The complete executable
was 15,214,445 bytes with SHA-256
`bc1f73cd81e95a20b4cb9e2fa151f93448ba197d546437ba7a4dcc19aba49c79`.

## Calling a migrated Tcl package

At `43755b2`, both variants ran the same entry and field-name package from
`examples/mixed-migration`. The Tcl-only variant used the original caption
package and a manifest with zero X modules. The mixed variant called an X
export and passed back into Tcl to look up the field name. Both used the
same Tcl procedure to dispatch and check each callback.

| Measurement | Tcl-only project | Mixed project |
| --- | ---: | ---: |
| Check in a fresh process | 120 ms | 145 ms |
| Pack in a fresh process | 1.44 s | 1.80 s |
| Start from source and render one caption | 126 ms | 135 ms |
| Start from an archive and render one caption | 82.5 ms | 83.1 ms |
| One callback in a batch of 40,000 | 2.78 µs | 8.34 µs |
| Observed peak process working set for the batch | 17.29 MiB | 18.10 MiB |
| Archive containing source and benchmark entry | 89,672 bytes | 102,513 bytes |

The callback ran 10,000 cycles over four inputs, including leading zeros,
Unicode and empty text. Each call checked the exact returned caption.
The in-process timer covered dispatch and verification. The startup rows
included launching the process and servicing one callback through the Tcl
event loop. The controller sampled the Windows peak working set about every
three milliseconds. Seven measured rounds followed a warm-up and alternated
the order of the variants.

The extra checked crossings cost about 5.6 µs per caption in this small leaf.
A conversion that keeps more work on one side of the boundary needs its own
comparison. Both variants used the same 15,223,467-byte executable with SHA-256
`e4ac637ad32ef19e06ede9b61e0c71456293cdc30700b979f67190a6730341bd`.
